# 面板多后端与安装器重构计划

## Context（背景与目标）

上轮 ThinkPHP 8 重构已完成并通过 127 项验收（16 控制器 / 9 中间件 / 32 路由，代码已推送）。现按新要求做一轮架构级重设计：

1. **去环境变量**：不采用任何 env 配置，`getenv` 全部移除
2. **install.php 一键安装**：所有参数经网页安装器写入数据库，装完即用
3. **不兼容旧版及旧数据库**：全新安装，删除全部 legacy 兼容路径
4. **多 Nightscout 后端**：后端入库（友好名称 + URL + 管理密钥），注册时下拉选择（显示友好名）
5. **管理员一键迁移**：某后端全部用户迁到另一后端，全量历史数据搬迁，用户无感
6. **用户名以面板为准**：面板用户名全局唯一，Nightscout subject/角色由面板派生与重建
7. **简化页面操作**：导航 9 项 → 5 项，个人相关四页合并为"设置"标签页

技术前提已核实（fork 权限模型）：
- 管理密钥持有 `api:entries:read`（整库读写），可按 `device` / `enteredBy` 跨 subject 读写任意用户数据（lib/authorization/index.js:360-386）
- `createSubject` 幂等（重名 400 → 列表取回），配合"先删后建"可完全按面板意志重建身份
- entries/treatments 不随 subject 删除连带，清理需按 `find[device]`/`find[enteredBy]` 批量 DELETE

## 已确认的决策

| 决策点 | 用户选择 |
|---|---|
| 加密密钥位置 | **全部入库**（panel_settings.key_seed）；缓解：`data/` 收紧 0770、DB 文件 chmod 0600 |
| 迁移数据范围 | **全量历史**（entries / treatments / devicestatus / profile store） |
| 源端旧数据 | **默认保留**，迁移表单勾选后才清理 |

## 一、数据层（app/library/Db.php）

- 新表 `panel_ns_backends`：`id, name TEXT UNIQUE COLLATE NOCASE, url TEXT, secret_enc TEXT, enabled INTEGER DEFAULT 1, created_at`
- `panel_users` 增加 `backend_id INTEGER REFERENCES panel_ns_backends(id)`
- `SCHEMA_VERSION` → 2；发现 v1 旧库直接报错拒绝（不做兼容）
- **密钥入库**：`keys()` 简化为单键 `sha256('night-panel|db-v2|' . setting('key_seed'))`；`keySeed()` 改为从 `panel_settings.key_seed` 读取，无则生成 64-hex 写入。**删除**：`<db>.key` 文件逻辑、legacy path-salt 回退、`PANEL_SECRET_KEY` env、legacy in-DB seed 迁移代码
- 缓解措施：建库目录 `mkdir 0770`；首次建库后对 DB 文件 `chmod 0600`
- helpers.php `panel_db_file()`：去掉 `PANEL_DB` env，固定返回 `panel/data/panel.db`；测试场景改用 `defined('PANEL_DB_FILE')` 常量注入（测试 bootstrap 里 define，不用 getenv）

## 二、安装器（public/install.php，新增，独立于框架）

- 独立入口（不经路由），自带 `session_start()` + CSRF token，自包含 HTML（不依赖 think-view）
- **锁机制**：`data/install.lock` 存在 → 拒绝；DB 已有用户/已有 key_seed → 拒绝（防误装误清）
- 向导四步：
  1. **环境自检**：PHP ≥ 8.1、pdo_sqlite/openssl/curl/json、`data/` 可写（自动建 0770）、`runtime/` 可写
  2. **管理员账号**：用户名 + 密码（≥ 8 位）+ 确认
  3. **第一个 Nightscout 后端**：友好名 + URL + 管理密钥，附"测试连接"按钮（AJAX 调 `/api/v1/status.json` 实时验证）
  4. **站点选项**：默认语言（zh_cn/en）、是否信任反代 HTTPS 头（trust_proxy）
- 提交动作：建库建表 → 写 `key_seed` → 写管理员（password_hash）→ 插入后端行（管理密钥 `enc:v1:` 加密）→ 写设置 → `touch install.lock` → 302 到 `/login`
- **EnsureInstalled 中间件**（新增，置于全局链首位）：未安装（无锁）时一切面板路由 302 → `/install.php`；`StartSession` 里现有的 `Auth::bootstrapAdmin()` 调用与 `PANEL_ADMIN_USER/PANEL_ADMIN_PASS` 逻辑删除

## 三、配置层（NsConfig.php 重写为 Backends 仓库）

- **删除**：`NIGHTSCOUT_URL` / `NIGHTSCOUT_ADMIN_SECRET` env 优先链、`NsConfig::baseUrl()/adminSecret()/source()` 的 env 分支
- 新 `app/library/Backends.php`：
  - `all() / enabled() / find($id)`
  - `clientFor($backendId 或行数组): NsClient`（NsClient 构造签名不变，直接复用）
  - `create / save`（管理密钥留空不改）/ `delete`（**有用户挂载的后端禁止删除**）
  - `countUsers($id)`、`testConnection($id)`（status.json 探活）
- 所有原本取 `NsConfig::client()` 的调用点改为取"用户所属后端"的 client：`SyncRunner`、`TreatmentService`（live 读写）、`ReadingService`、`ProfileService`、`HealthRunner`、`UserProvisioner`、`UserProvisioner::revoke`、`AdminController` 健康检查

## 四、用户面（注册选后端；用户名以面板为准）

- `UserService::register` 接受 `backend_id`（必须是 enabled 后端），存入 `panel_users.backend_id`
- `UserProvisioner::provision($username, NsClient $client)` 改为显式传入目标后端 client
- 注册表单 `register.html`：后端下拉（友好名 + 仅 enabled）；无可用后端时禁用注册并提示
- 无 enabled 后端时管理员页显著提示"请先添加后端"
- **以面板为准**：目标后端已有同名 subject 时 → 先 `DELETE` 再重建（拿到新 token 与正确角色），不沿用旧 subject
- `myapi` 页改为显示"当前后端：友好名"

## 五、管理员后端管理与一键迁移

### 后端管理（admin.html 重构原 NS 设置区块）
- 列表：友好名 / URL / 用户数 / 启用状态 / 连通测试按钮
- 添加 / 编辑（名称、URL、管理密钥留空不改）、启用 / 停用、删除（有用户禁止）

### 一键迁移（app/service/BackendMigration.php，新增）
- 表单：源后端（仅列有用户的）+ 目标后端 + 勾选框"迁移完成后清理源端数据"（默认不勾）
- 确认页列出受影响用户清单 → 执行（`set_time_limit(0)`，逐用户同步处理）：
  1. 目标端重建身份：角色幂等建 → subject 删旧建新 → 新 token
  2. 全量数据搬迁（源端管理密钥读、目标端管理密钥写，分页批量）：
     - entries：按 `find[device]=username` + 时间窗分页读，批量 POST（保留原 date/device/type/sgv）
     - treatments：按 `find[enteredBy]=username` 分页读，POST 保留原 created_at
     - devicestatus：按 `find[device]=username`
     - profile store：读源端 `store[username]`，用**新用户 token** 按现有 provision 的合并语义写入目标端
  3. 更新 `panel_users.backend_id` + 新 token 加密存储
  4. **清空该用户的面板镜像与游标**（`panel_entries/treatments/devicestatus` + `panel_sync_state`，防止新旧 ns_id 双计数），下次 cron 从新后端重灌
  5. 勾选清理时：源端按 `find[device]` / `find[enteredBy]` 批量 DELETE entries/treatments/devicestatus，再删 subject/角色
- 结果页：每用户 成功（含搬运条数）/ 失败（原因）汇总；失败用户可整批重试（幂等）
- NsClient 增补：`bulkPostEntries` / `bulkPostTreatments`（数组提交）、`deleteEntriesByDevice` / `deleteTreatmentsByEnteredBy` / `deleteDeviceStatusByDevice`（find 批量 DELETE）、`deleteSubjectByName`

## 六、页面操作简化（UX）

- 导航 **9 → 5**：仪表盘、填写数据、我的记录、统计报告、设置（管理员另见"管理"）
- 新 `view/settings.html`：单页四标签——我的 Profile / 治疗方案 / 提醒设置 / 我的 API
- **控制器与路由保持不变**（`/profile`、`/profile/plans`、`/settings/alerts`、`/myapi` 仍各自响应），仅合并展示模板并重排导航——低风险合并
- dashboard 顶部加快捷入口（填写数据 / 我的记录）
- lang 增补"设置"标签等文案，zh/en 键保持全等（lang-test 校验）
