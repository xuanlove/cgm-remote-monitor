What it is

A monitor without a waiting room.

A physical CGM only talks to the device next to it. Nightscout puts that data on the internet — securely, on your own server — and keeps everyone in the loop. It stores sensor glucose values, treatments and device status in MongoDB, then serves them to any browser or client that asks.

01

Sensor

Your CGM records interstitial glucose every few minutes, day and night.

02

Uploader

xDrip+, Loop, AndroidAPS, Dexcom Share, LibreLinkUp or your own script pushes readings to the API.

03

Nightscout

The Node.js server stores everything in MongoDB, forecasts 30 minutes ahead and evaluates alarms.

04

Everyone

Caregivers watch the live dashboard, receive alerts, or build on the REST and WebSocket APIs.

Features

More than a number on a screen.

Nightscout started as a remote glucose view. Today it is a full care dashboard, built and extended by the people who use it.

Live dashboard

Current BG, delta and trend arrow, a 24-hour trace, and configurable target lines — updated over Socket.IO.

Predictive alarms

AR2 forecasting looks 30 minutes ahead. Simple threshold alarms, snooze windows and stale-data warnings keep watch.

Care Portal

Log carbs, insulin, finger checks, notes, and site, sensor, insulin or battery changes in one place.

Insulin & carb insights

Insulin-on-board, carbs-on-board, active basal and a bolus-wizard preview, calculated from your treatment profile.

Supply & device timers

Cannula, sensor, insulin and pump-battery age at a glance, with reminders before things need changing.

Nightscout Connect

Pull data from Dexcom Share, LibreLinkUp, Glooko, MiniMed CareLink or another Nightscout site.

Open API

REST v1 and token-secured v3, live WebSocket updates, and Swagger docs served at /api-docs/.

Built for everyone

25 languages, colorblind-friendly and night themes, responsive layouts, and support for older tablets.

NightPanel: one Nightscout, many people.

NightPanel is a multi-user panel shipped alongside Nightscout. It treats Nightscout as a pure backend, adds registration, per-user profiles and isolated access, then mirrors each account's data into a local SQLite database for fast dashboards, reports and alerts.

Multiple backends

Register several Nightscout sites by friendly name. Each account belongs to one backend and always talks to it.

Per-user isolation

Registration provisions a profile named after the user and a scoped token. Entries and treatments are attributed on the server, so users only see their own data.

Local mirror, fast pages

A cron job pulls each account incrementally with a 6-hour overlap. Pages read SQLite instead of Nightscout, and show a delay warning when data is stale.

Reports & exports

TIR, TAR and TBR, GMI, CV, low-glucose events and coverage for 7–90 days, plus CSV and JSON export.

Treatments & alerts

Add glucose and 20 treatment types, edit or delete your records, set personal thresholds and get browser notifications.

Drop-in API

Panel endpoints mirror Nightscout API v1, so xDrip+, Loop and AndroidAPS can upload straight to the panel.

Architecture & data flow

The web tier only reads SQLite. Writes go to the Nightscout API, and a scheduled sync keeps the mirror current; Nightscout and MongoDB remain the source of truth.

Web read path Write path Background sync

01Security & tenant isolation

  • Web pages read only the local mirror; write forms are CSRF-guarded and proxied to Nightscout.
  • Scoped tokens allow profile read, write and create for the caller's own store[<username>], read of their own device's entries, and create-only access to entries, treatments and devicestatus.
  • Attribution is enforced server-side: device=<username> on entries, enteredBy=<username> on treatments.
  • Backend API secrets are encrypted with AES-256-GCM; the installer writes install.lock and the panel needs no environment variables.

02Sync engine & storage

  • A per-user, per-stream millisecond cursor lives in panel_sync_state; every pull re-reads a 6-hour overlap so late uploads are not missed.
  • Records are upserted idempotently by Nightscout _id; a 30-day full recalibration repairs cursor drift.
  • Pages read panel_entries, panel_treatments, panel_devicestatus and panel_profiles.
  • Retention defaults: glucose 120 days, treatments 365, logs 7, alert events 30.

03Nightscout-compatible API

  • Reads: /api/v1/entries.json, treatments.json, devicestatus.json, profile.json, profile/current and status.json.
  • Writes: POST entries, treatments and devicestatus, plus PUT profile.json; point uploaders at https://panel.example.com/api/v1/.
  • Reads accept a session or api-secret; writes require api-secret. Limits: 120 requests/min per IP, JSON errors for 401, 400, 429 and 502.
  • Entries and treatments support Last-Modified / If-Modified-Since and answer 304 when unchanged.

04Deployment & operations

  • Serve panel/public behind nginx or Apache with php-fpm; app/, config/, runtime/, vendor/ and data/ stay outside the document root.
  • PHP 8.1+ with curl, openssl, pdo_sqlite and sqlite3; Composer 2; OPcache recommended.
  • /install.php creates the admin, encryption seed, default language and first backend, then locks itself.
  • The admin area adds or tests backends, suspends registration by disabling a backend, deletes users, and migrates accounts between backends idempotently.

Scheduled jobs

Run as the php-fpm user. The SQLite database must stay outside the web root.

Set AUTH_DEFAULT_ROLES=denied on every Nightscout backend — the default readable role would otherwise expose data.
crontab 
# incremental sync, every minute
* * * * *   php /var/www/cgm-remote-monitor/panel/bin/sync.php

# profile snapshot, every 15 minutes
*/15 * * * * php /var/www/cgm-remote-monitor/panel/bin/sync.php --profiles

# 30-day recalibration, daily at 03:05
5 3 * * *    php /var/www/cgm-remote-monitor/panel/bin/sync.php --full --days=30

# retention cleanup, daily at 03:30
30 3 * * *   php /var/www/cgm-remote-monitor/panel/bin/cleanup.php

Get started

From clone to dashboard.

Nightscout runs anywhere Node.js and MongoDB run. This walkthrough uses this repository and covers required variables, Docker and platform templates, TLS behind a reverse proxy, and the final checks.

01

Prepare the host

Node.js 20 LTS or later (22 and 24 are supported) and MongoDB 5.0.32+ or 6.0.27+; 4.4 is deprecated. The repository also ships Docker, Heroku and Azure templates.

02

Clone this repository & install

Clone this repository as a non-root user and run npm ci. The post-install step bundles the client with webpack and generates a cache key.

03

Set required & production variables

Provide a MongoDB URI, an API secret of at least 12 characters and display units; then review BASE_URL, ENABLE, AUTH_DEFAULT_ROLES and TRUST_PROXY.

04

Start, verify & connect an uploader

Run npm start, check /api/v1/status.json, then point your uploader at the site with the autoconfigure tool.

quick start 
# 1. Clone this repository
git clone https://github.com/xuanlove/cgm-remote-monitor.git
cd cgm-remote-monitor
npm ci          # postinstall builds the client bundle

# 2. Required environment
export MONGODB_URI="mongodb://user:pass@host:27017/nightscout"
export API_SECRET="at-least-12-characters"
export DISPLAY_UNITS="mg/dl"

# 3. Start and verify
npm start
curl "http://localhost:1337/api/v1/status.json"

Environment reference

Three values are required. The rest are production settings worth reviewing before you expose the site.

Variable Default / required Purpose
MONGODB_URI required MongoDB connection string. Docker Compose uses MONGO_CONNECTION.
API_SECRET required At least 12 characters, or a path in API_SECRET_FILE.
DISPLAY_UNITS mg/dl mg/dl or mmol/L for the whole site.
BASE_URL — Public URL used in links and callbacks.
ENABLE — Space-separated plugins such as careportal iob cob.
AUTH_DEFAULT_ROLES readable Set denied to require a token; required for NightPanel isolation.
TRUST_PROXY — 1 behind one proxy; false to ignore forwarded headers.
PORT 1337 Node listener. Keep it on a private interface.
INSECURE_USE_HTTP false true only when TLS is terminated by a trusted proxy.
API3_SECURITY_ENABLE true Never disable on a site with real data.

Reverse proxy & TLS

Terminate TLS at nginx or Apache, keep port 1337 off the public interface, and set TRUST_PROXY so forwarded headers are trusted only from the proxy.

nginx.conf 
server {
    listen 443 ssl;
    server_name nightscout.example.com;

    location / {
        proxy_pass http://127.0.0.1:1337;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

HSTS is on by default. See SECURE_HSTS_HEADER and the proxy guidance in the README.

Before you connect an uploader

  • MongoDB is reachable, backed up, and not exposed to the internet.
  • API_SECRET is at least 12 characters and AUTH_DEFAULT_ROLES matches who should read the site.
  • BASE_URL and TRUST_PROXY match the public URL and proxy; port 1337 is not public.
  • /api/v1/status.json answers, /api-docs/ loads, and the uploader points at the site URL.
