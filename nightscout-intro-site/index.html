What it is

A monitor without a waiting room.

A physical CGM only talks to the device next to it. Nightscout puts that data on the internet — securely, on your own server — and keeps everyone in the loop. It stores sensor glucose values, treatments and device status in MongoDB, then serves them to any browser or client that asks.

01

Sensor

Your CGM records interstitial glucose every few minutes, day and night.

02

Uploader

xDrip+, Loop, AndroidAPS, Dexcom Share, LibreLinkUp or your own script pushes readings to the API.

03

Nightscout

The Node.js server stores everything in MongoDB, forecasts 30 minutes ahead and evaluates alarms.

04

Everyone

Caregivers watch the live dashboard, receive alerts, or build on the REST and WebSocket APIs.

Features

More than a number on a screen.

Nightscout started as a remote glucose view. Today it is a full care dashboard, built and extended by the people who use it.

Live dashboard

Current BG, delta and trend arrow, a 24-hour trace, and configurable target lines — updated over Socket.IO.

Predictive alarms

AR2 forecasting looks 30 minutes ahead. Simple threshold alarms, snooze windows and stale-data warnings keep watch.

Care Portal

Log carbs, insulin, finger checks, notes, and site, sensor, insulin or battery changes in one place.

Insulin & carb insights

Insulin-on-board, carbs-on-board, active basal and a bolus-wizard preview, calculated from your treatment profile.

Supply & device timers

Cannula, sensor, insulin and pump-battery age at a glance, with reminders before things need changing.

Nightscout Connect

Pull data from Dexcom Share, LibreLinkUp, Glooko, MiniMed CareLink or another Nightscout site.

Open API

REST v1 and token-secured v3, live WebSocket updates, and Swagger docs served at /api-docs/.

Built for everyone

25 languages, colorblind-friendly and night themes, responsive layouts, and support for older tablets.

Developer API

Your data, on your terms.

Everything the dashboard shows is available over HTTP. Query CGM entries, treatments and profiles, inspect server status, or build your own client — no Mongo access required.

GET /api/v1/entries Sensor glucose values
GET /api/v1/treatments Care Portal records
GET /api/v1/profile Treatment profiles
GET /api/v1/status.json Status & settings
ANY /api/v3/* Token-secured API v3
Browse the OpenAPI spec ↗
terminal 
# Latest 10 sensor glucose values
curl "$NIGHTSCOUT_URL/api/v1/entries.json?count=10"

# Find readings around 100 mg/dL
curl "$NIGHTSCOUT_URL/api/v1/entries.json?find[sgv]=100"

# Treatments, profiles, status…
curl "$NIGHTSCOUT_URL/api/v1/status.json"

# Interactive Swagger docs on your instance
open "$NIGHTSCOUT_URL/api-docs/"

Get started

From clone to dashboard.

Nightscout runs anywhere Node.js and MongoDB run: a VPS, a Raspberry Pi, Docker, or a platform like Heroku or Azure.

01

Provision the basics

Node.js 20 LTS or later, and MongoDB 5.0.32+ or 6.0.27+. The project also ships Docker, Heroku and Azure templates.

02

Clone & install

Install dependencies as a non-root user. The post-install step bundles the client with webpack and generates a cache key.

03

Configure

Three values are required: a MongoDB URI, an API secret of at least 12 characters, and your display units. Add ENABLE for extra features.

04

Point your uploader & go live

Start the server, open port 1337 (or your reverse proxy), then connect your uploader using the autoconfigure tool.

quick start 
# 1. Clone the project
git clone https://github.com/nightscout/cgm-remote-monitor.git
cd cgm-remote-monitor
npm install

# 2. Required configuration
export MONGODB_URI="mongodb://user:pass@host:27017/nightscout"
export API_SECRET="at-least-12-characters"
export DISPLAY_UNITS="mg/dl"

# 3. Start
npm start

# → http://localhost:1337
